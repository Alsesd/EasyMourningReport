Легкий, надійний та зручний веб-застосунок для збору та обробки щомісячних товарних звітів із кількох магазинів. Він допомагає автоматизувати рутинну роботу адміністратора, скорочує помилки при підрахунках і забезпечує прозорий контроль над звітами, цінами та історією змін.

## Про проєкт

`EasyMourningReport` призначений для компаній, де кілька торгових точок регулярно подають звіти про продажі. Замість ручного ведення Excel-таблиць або розкиданих форм, система централізує весь процес в одному веб-додатку.

Адміністратор:
- веде каталог товарів та цін;
- додає магазини та користувачів;
- контролює звіти по місяцях;
- переглядає журнал дій та історію змін;
- керує публічним тунелем прямо в панелі налаштувань.

Магазин:
- входить у систему;
- обирає місяць;
- вносить лише кількості товарів;
- зберігає чернетку або надсилає звіт;
- отримує автоматично підраховані суми.

## Чому це корисно

- зменшує ручний ввод даних;
- знижує ризик помилок у підрахунках;
- спрощує контроль за кількома магазинами;
- зберігає історію змін цін та звітів;
- дозволяє керувати процесом без окремого складного ERP-пакету;
- розгортається однією командою через Docker Compose без складних налаштувань.

## Основні можливості

- **Сучасний клієнтський SPA-інтерфейс**: React 18, TypeScript, Tailwind CSS, Radix UI та TanStack Query без жодних сторонніх CDN-залежностей на етапі виконання.
- **Окремі оптимізовані робочі простори**:
  - *Для магазину*: зручний мобільний екран (`/report`) з великими кнопками крокового введення (stepper), підтримкою швидкого введення на телефоні, збереженням чернеток та підтвердженням відправки.
  - *Для адміністратора*: адаптивна панель (`/admin/*`) — бічна панель на десктопі, нижня панель на мобільних пристроях.
- **Повна підтримка офлайн-роботи (PWA)**: сервіс-воркер кешує ресурси застосунку, а чернетки звітів зберігаються локально в браузері та автоматично синхронізуються при відновленні з'єднання.
- **Управління товарами та цінами**: швидкий пошук, зміна ціни в одне поле з компактною історією за поточний місяць, архівування та відновлення.
- **Масовий імпорт з Excel (.xlsx)**: колонка A — назва, колонка B — ціна.
- **Експорт зведеного звіту в Excel (.xlsx)**: пряме скачування файлу зведення за вибраний місяць.
- **Керування магазинами та обліковими записами**: створення, редагування, скидання паролів, архівування.
- **Щомісячні звіти та блокування**: перегляд поданих звітів, детальний перегляд із можливістю розблокування/блокування.
- **Журнал аудиту**: детальний аудит дій у системі з фільтрацією за типами подій та пошуком.
- **Керування публічним тунелем**: статус тунелю Cloudflare, перемикач автозапуску та запуск/зупинка безпосередньо з панелі налаштувань.
- **Автоматичні резервні копії**: скачування знімка бази даних в один клік і регулярне резервне копіювання.
- **Безпека**: збереження паролів через PBKDF2-хешування із сіллю, захист сесій та перевірка походження запитів.

## Технологічний стек

- **Бекенд**:
  - Python 3.11+
  - FastAPI & Starlette
  - Uvicorn
  - SQLModel (SQLAlchemy Core) & SQLite
  - PDM (керування залежностями, PEP 621)
  - openpyxl (генерація та парсинг Excel)
- **Фронтенд**:
  - React 18 & TypeScript (суворий режим)
  - Vite 6
  - Tailwind CSS 3
  - Radix UI (доступні модальні вікна та примітиви)
  - TanStack Query v5 (серверний стан, кешування та оптимістичні оновлення)
  - React Router v6 (маршрутизація з code-splitting)
  - Lucide React (іконки)
  - Самостійний шрифт **Onest** (`@fontsource/onest`) без зовнішніх запитів до Google Fonts чи CDN
- **Інфраструктура**:
  - Docker & Docker Compose (багатоетапна збірка: Stage 1 Node.js build → Stage 2 Python builder → Stage 3 Minimal runtime)
  - Cloudflare Tunnel (швидкий TryCloudflare Quick Tunnel або власний іменований тунель)

## Розгортання через Docker Compose (Рекомендовано)

Застосунок повністю готовий до роботи «з коробки» з мінімальною кількістю команд і прапорців.

### Запуск в один крок

```bash
docker compose up -d
```

Усе налаштовується автоматично:
1. Застосунок створить базу даних і збереже її у volume `data`.
2. Одноразовий пароль адміністратора виводиться в логи:
   ```bash
   docker compose logs app
   ```
3. Контейнер `tunnel` автоматично створить швидкий захищений HTTPS-тунель (**TryCloudflare Quick Tunnel**) і запише його URL у статус.
4. Адреса публічного тунелю відображається в логах:
   ```bash
   docker compose logs tunnel
   ```
   А також безпосередньо у веб-панелі адміністратора на сторінці **«Налаштування»**.
5. Локально застосунок доступний за адресою `http://localhost:8000`.

### Налаштування власного тунелю (Опціонально)

Створіть `.env` файл за потреби:
```bash
cp .env.example .env
```

Щоб використовувати власний постійний домен через Cloudflare Tunnel, просто вкажіть токен у `.env`:
```dotenv
TUNNEL_TOKEN=eyJh...
PUBLIC_URL=https://report.yourdomain.com
```

І перезапустіть:
```bash
docker compose up -d
```

Якщо ви хочете тимчасово вимкнути тунель, встановіть `TUNNEL_ENABLED=false` у `.env`.

## Локальна розробка

### 1. Бекенд (Python & FastAPI)

Встановлення залежностей:
```bash
pdm install
```

Запуск сервера розробки:
```bash
pdm run uvicorn app.main:app --reload
```

Запуск бекенд-тестів:
```bash
pdm run pytest
```

### 2. Фронтенд (React, TypeScript & Vite)

Усі файли клієнтського застосунку знаходяться у директорії `frontend/`.

Встановлення залежностей:
```bash
cd frontend
npm install
```

Запуск сервера розробки Vite з проксіюванням API на бекенд (`http://localhost:8000`):
```bash
npm run dev
```

Перевірка лінтером та типами:
```bash
npm run lint
npm run typecheck
```

Запуск юніт-тестів (Vitest):
```bash
npm test -- --run
```

Збірка у продакшн (результат записується в `app/static/app/`):
```bash
npm run build
```

Оновлення типів API з OpenAPI-схеми бекенда:
```bash
npm run gen:api
```

## Безпека та резервні копії

- Паролі зберігаються у вигляді PBKDF2-хешів із випадковою сіллю.
- Адміністративний пароль генерується автоматично при першому запуску, якщо не задано `ADMIN_PASSWORD`.
- Резервні копії бази даних автоматично створюються під час запуску, зупинки та щогодини при активності (зберігаються у volume `backups`).
- Секретний ключ сесії генерується автоматично у `secret.key` або задається через `SECRET_KEY`.
