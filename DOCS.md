# Технічна документація EasyMourningReport

## Призначення

EasyMourningReport — серверний FastAPI/Jinja2-застосунок для щомісячних товарних звітів. Браузерний інтерфейс використовує HTML-шаблони, CSS і невеликі JavaScript-модулі; окремий Node/Vite build для фронтенду не потрібен.

## Архітектура

- `app/main.py` створює FastAPI-застосунок, підключає middleware, статичні файли, маршрути та життєвий цикл.
- `app/routes/` обробляє HTTP-запити й перевірку доступу.
- `app/services/` містить бізнес-логіку, зокрема роботу з цінами та Excel.
- `app/db/` містить моделі, підключення до SQLite, репозиторії, міграції та резервне копіювання.
- `app/templates/` містить Jinja2-шаблони сторінок.
- `app/static/` містить CSS, JavaScript, іконки та ресурси PWA.
- `run.py` є спільною точкою входу для запуску з вихідного коду та EXE.
- `start.bat` є Windows-обгорткою запуску; за наявності Tailscale вона може перевірити з'єднання й увімкнути Funnel.
- `.github/workflows/build-windows.yml` запускає тести та збирає Windows EXE через PyInstaller.

## Клієнтський рендеринг

Каталог товарів, магазини, редагування звітів, звіти адміністратора, зведення та журнал відображаються в браузері через Alpine.js. Jinja2 віддає легкий HTML-shell, а сторінкові модулі в `app/static/*-app.js` завантажують DTO через `/api/v1`, оновлюють DOM і показують стани завантаження/помилки. `app/static/api-client.js` централізує same-origin JSON-запити з наявною cookie-сесією. Для форм, що змінюють дані, API перевіряє Origin/Referer; браузерна авторизація залишається на сервері.

Компоненти сторінки та API-клієнт мають завантажитися **до** Alpine.js: Alpine сканує `x-data` одразу під час запуску. Базовий шаблон саме в такому порядку завантажує скрипти. Якщо Alpine не завантажився ні локально, ні з резервного CDN, користувач бачить повідомлення замість порожньої сторінки.

У репозиторії не потрібен Node/npm build. Windows workflow завантажує точну версію Alpine в `app/static/alpine.min.js` перед перевірками та включає її в one-file EXE. У звичайному source checkout, де цього build-артефакту немає, шаблон має резервне завантаження з закріпленого CDN. Після першого відкриття успішні локальні запити до статичних ресурсів кешуються service worker; кеш версіонується через `app/static/sw.js`.

## Історія цін у межах місяця

У моделі `ProductPrice` початкова зміна за місяць зберігається з ключем `YYYY-MM`, а наступні — `YYYY-MM_1`, `YYYY-MM_2` тощо. Номер суфікса сортується чисельно, щоб десята зміна йшла після дев'ятої, а не перед другою. Це зберігає кожну послідовну зміну без зміни таблиці та без стирання попередніх значень.

`month_price_timeline()` повертає для адмінського UI ціну, що діяла на початку місяця, а потім кожну зміну за цей місяць — навіть якщо ціна повернулась до раніше використаної. `offered_prices()` для форми звіту прибирає повторні однакові суми: вводиться окрема кількість для кожної унікальної ціни, і не виникають два поля з однаковим ключем товару/ціни. Ціни, за якими вже збережено кількості, залишаються в звіті. У наступному місяці за замовчуванням діє остання ціна з попереднього місяця; старі рядки звітів не перераховуються.

Після зміни JS/CSS або шаблонів перевіряйте завантаження всіх Alpine-компонентів, перемикання вкладок, редагування товарів, збереження звіту й історію з трьома або більше цінами в одному місяці.

## Запуск із вихідного коду

Потрібні Python і Poetry:

```bash
poetry install
poetry run python run.py
```

За замовчуванням сервер слухає `127.0.0.1:8000`. Значення можна перевизначити змінними середовища `HOST` та `PORT`.

Для Nix-середовища:

```bash
nix develop
poetry install
serve
```

## Дані та резервні копії

SQLite-база, ключ сесій та резервні копії — це постійні дані, не ресурси збірки. Не видаляйте їх під час оновлення:

- `reports.db` — база звітів;
- `secret.key` — ключ підпису сесій; його заміна може завершити активні сесії;
- `backups/` — резервні копії.

У замороженому EXE дані мають залишатися поза тимчасовим каталогом розпакування PyInstaller. Каталог за замовчуванням розташовується поруч із EXE, якщо він доступний для запису; інакше Windows використовує `%LOCALAPPDATA%\\LegkyiZvit`. `LEGKYI_DATA_DIR` дозволяє задати власний каталог. Під час перенесення встановлення копіюйте базу та ключ разом і зберігайте резервні копії.

## Windows EXE та PyInstaller

Для локальної збірки на Windows:

```powershell
python -m poetry install
python -m poetry run python -m pip install pyinstaller==6.16.0
python -m poetry run pyinstaller --noconfirm --clean --onefile --console --name LegkyiZvit --add-data "app/templates;app/templates" --add-data "app/static;app/static" --collect-all fastapi --collect-all starlette --collect-all sqlmodel --collect-all sqlalchemy --collect-all jinja2 --collect-all openpyxl --collect-all uvicorn run.py
```

Результат — `dist/LegkyiZvit.exe`. PyInstaller збирає Python та залежності в один файл і включає шаблони та статичні ресурси. Не запускайте EXE безпосередньо з вікна перегляду ZIP: спочатку розпакуйте файл у постійну теку.

CI виконує такі кроки по порядку:

1. Встановлює залежності з Poetry.
2. Запускає `pytest`.
3. Збирає EXE.
4. Перевіряє наявність та розмір EXE.
5. Запускає EXE у тимчасовому каталозі даних і робить HTTP smoke-тест.
6. Завантажує EXE як артефакт; для тегів `v*` та `Soup.v*` прикріплює його до GitHub Release.

Якщо тестування або smoke-тест завершується помилкою, збірка не публікується.

## Tailscale та Funnel

У Windows `start.bat` використовує встановлений Tailscale CLI. Коли Tailscale не підключений, скрипт запускає `tailscale login`, після чого користувач завершує вхід у браузері. Авторизаційний стан зберігається самим Tailscale; не потрібно зберігати reusable auth key у файлі скрипта чи репозиторії.

Funnel може працювати лише за умови, що його дозволено політиками tailnet. Якщо Tailscale або Funnel недоступний, застосунок має продовжувати запуск у локальному режимі. Прапорець `COOKIE_SECURE=1` слід установлювати лише тоді, коли HTTPS Funnel успішно запущено.

## Тестування

Запустіть:

```bash
poetry run pytest -q
```

Тести мають проходити перед збиранням релізу. Окремо перевіряйте Windows-EXE smoke-тестом, оскільки успішні unit/integration тести самі по собі не доводять, що PyInstaller включив усі runtime-залежності та ресурси.

## Оновлення встановленої версії

1. Зупиніть застосунок.
2. Зробіть копію `reports.db`, `secret.key` та `backups/`.
3. Розпакуйте новий EXE або ZIP у постійну теку.
4. Перенесіть/залиште дані у відповідному каталозі даних.
5. Запустіть нову версію та перевірте вхід, сторінки звітів і експорт Excel.
6. Не замінюйте `secret.key` без потреби: це призведе до завершення активних сесій.
